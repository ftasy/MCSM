MC 服务器管理器 —— 更新日志
================================================================

当前版本：v0.2（2026-10-25）
上一个正式版：v0.1.1

----------------------------------------------------------------
v0.2  发布版（2026-10-25）
----------------------------------------------------------------

【性能优化】
  · 新增「启用 Aikar 性能优化 (G1GC)」开关（服务器配置 → 启动设置）。
    启用后自动注入 PaperMC 官方推荐的 18 项 G1GC 启动参数，
    并强制最大内存与最小内存一致（Aikar 的前提）。
  · 覆盖两种启动方式：
      - 常规 jar 启动：QProcess 直接注入参数；
      - 新版 Forge / NeoForge（args 文件启动）：自动写入 user_jvm_args.txt。
  · 「重新生成 run.bat」也会按开关生成带 Aikar 参数的脚本。
  · 勾选开关时自动把最大内存同步为最小内存，避免误配。

----------------------------------------------------------------
v0.1.1  发布版（2026-10-25）
----------------------------------------------------------------

【网络与镜像】
  · 统一 User-Agent（MCServerManager/0.1），镜像站不再拒连。
  · 修复 MCIM 镜像 API 404：Modrinth 基址补全为 /modrinth/v2。
  · Forge / NeoForge 元数据接入 BMCLAPI2 加速，失败自动回退官方源。
  · NeoForge 1.20.1（47.x）镜像缺失时自动用官方源兜底。
  · 模组哈希批量查询 / 更新接口自动走镜像，失败回退官方。

【模组下载引擎】
  · 模组下载改为 4 线程并发，不再一个一个排队。
  · 官方 CDN 自动替换为 MCIM 镜像加速。
  · 新增 Fractureiser 木马特征扫描，命中即删除并拒装。
  · 下载支持断点续传（Range），网络闪断不用从头下。

【工程化 / 稳定性】
  · 启动器强制支持系统代理，挂加速器也能下载。
  · 新增全局文件日志 manager.log，崩溃自动记录。
  · 路径含 ! / # 时启动前弹窗警告，避免 Java 启动失败。
  · 修复 Forge / NeoForge 指定版本安装时二次联网校验
    因网络波动误报“没有这个版本”的问题（选中即直接下载）。
  · 网络故障时 Forge / NeoForge 版本列表如实提示“网络问题”，
    不再误报“没有版本”。

v6.0.0  发布版（2026-10-22）
----------------------------------------------------------------

【安装与发布】
  · 新增图形安装程序：双击 安装.bat，可勾选
      - 自动安装 Python（本机没有 Python 3.9+ 时，下载并静默安装 Python 3.12）
      - 安装 PySide6 界面库（已安装则自动跳过；失败会自动换国内镜像重试）
      - 创建桌面快捷方式
    并可自选安装目录，不需要管理员权限。
  · 新增卸载程序：卸载.bat，可选择删除程序文件、配置和桌面快捷方式。
  · 正式发布包不再附带 check_*.py、t_toggle.py 等开发工具，体积更小。
  · 新增 pack.py 打包脚本：发布包自动校验，拒绝 __pycache__、用户配置混入。

【服务器核心安装】
  · Paper 下载全面改用官方 Fill v3 接口。
    原 api.papermc.io/v2 已整体下线（实测全部返回 410），旧代码会先失败再回退。
  · Paper 旧版本（1.21.3 / 1.21.4，甚至 1.7.10 等）在 fill 站仍可下载，
    软件会自动处理；这些版本被官方标记为 UNSUPPORTED，不再修 bug / 补安全漏洞。
  · Fabric、Paper、Forge、NeoForge 的安装和加载器更新全部重新测试。
  · 修复 Forge 加载器更新永远提示“查不到版本”的问题。
  · 修复 Paper 加载器更新因参数名过旧而直接报错的问题。
  · Forge / NeoForge 更新会自动寻找可用的 Java；服务器配置里保存的 Java 也会带过去。
  · 更新加载器时（Fabric 服）可选“同时更新 Fabric API 前置模组”，默认勾选；
    旧版 Fabric API 会改名成 .old 留底，避免新旧两个版本同时加载。

【扫描与识别】
  · 加载器识别改为读取 jar 内部特征，不再只看文件名：
      - Paper 装成 server.jar 也能正确识别为 paper；
      - 原版 server.jar 不会再被误判成 Paper。
  · 扫描改到后台线程，服务器多、world 大时界面不再卡住；
    扫描过程中切换总目录会自动按新目录重新扫描。
  · 存档选择优先使用 server.properties 里的 level-name，
    并排除 backups 目录，不会再拿备份存档当主存档显示。

【启动 / 搬迁 / 导入】
  · 统一搬迁、拖放导入、工具栏“导入地图”全部改为后台线程，复制大存档不卡界面。
  · 搬迁/导入进行中关闭窗口会先确认，避免留下复制了一半的文件夹。
  · 启动时如果上次的总目录不存在（例如盘符换了），不再弹框卡住，只在状态栏提示。

【界面】
  · 顶部文字按钮新增悬停淡入、按下回弹动画。
  · 移除描边功能，只保留粗体设置。
  · 显示设置里的“PCL 风格”改名为“选中与悬停效果”，相关选项改成更直白的名字。
  · 移除“PCL 龙猫蓝”预设配色。
  · 主题配置损坏（例如颜色字段被写成 false）时自动恢复默认，避免界面异常。

【稳定性 / 清理】
  · 修复通过 Modrinth 下载/更新模组必定失败的问题（下载函数参数不匹配）。
  · 修复“已装 Fabric API 检测不到”的问题（之前扫错了目录）。
  · 修复主题文件中残留旧配色/坏值时界面异常的问题。
  · 修复关闭窗口时，后台服务器进程可能导致程序卡死或闪退的问题：
      定时器现在挂载了父对象；强杀进程后等待 500ms 防止出现僵尸进程。
  · 修复多开备份冲突（改用字典按服隔离）。
  · 修复 `analyze.py` 因旧函数名导致的静默报错。
  · 修复 `loaderup.py` 的正则识别不到新版 `neoforge` 的问题。
  · 修复扫描时网络接口查询报错不提示的问题。
  · 清理死代码 100 余处：重复定义的方法、没有任何入口的功能、
    未被调用的函数/常量、未使用的导入等。
  · 回归测试脚本改为写临时配置，不再覆盖用户的 theme.json。
