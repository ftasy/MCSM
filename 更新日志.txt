v2.3.6  关不掉 + 重启不接管（2026-11-04）
----------------------------------------------------------------

【关不掉：程序还在跑】
  - 根因一：关主窗口时会给每个运行中的服务器弹一个 **cmd 独立控制台**
    （tail 日志用的）。那是**独立进程**，主窗口关了它照样跑，
    看起来就像"启动器没关掉"，而且关不掉。
    现在改成**默认不弹**，需要的话在退出确认框里自己勾。
  - 根因二：「调出控制台」的独立窗口是**顶层窗口** —— 只要还有一个
    可见，QApplication 就不会退出，表现就是"点了关闭，程序还在跑"。
    现在退出时会把这些窗口全部关掉并清空引用。
  - 退出确认框重做，三个选项说清楚：
      · 退出并保留服务器（推荐）：服务器继续在后台跑，下次打开自动接管；
      · 全部停止并退出：先给服务器发 stop，**等它保存完世界**再退出
        （最多等 15 秒，超时才强杀）；
      · 取消。

【重启后自动接管：之前根本没接管】
  - 根因：接管检测固定在启动后 500ms 触发，那时目录扫描（异步线程）
    往往还没跑完，服务器列表还是空的 —— 一个服都接管不了。
  - 现在改成**扫描完成后再接管**（并保留自动重试兜底），
    接管成功状态栏会提示"已接管 N 个上次仍在运行的服务器"。
  - 接管回来的服务器控制通道已断（上个管理器的管道没了），
    控制台里写明了：日志可读、发指令不可用、点停止是直接结束进程
    （不保存世界，建议先在游戏里 save-all）。

【退出时服务器更稳】
  - 要保留的 QProcess 会脱离主窗口 + 断开信号 + 放进全局存活集合，
    免得主窗口销毁时连带把 java 进程带走（管道一关，服务器会莫名其妙挂）。

v2.3.5  『下载源设置』残留窗口根治（2026-11-04）
----------------------------------------------------------------

【为什么旧版会出现"模组搜索一直弹镜像源选择"】
  - v2.0.3 之前，『下载源设置』是非模态窗口（show() 而不是 exec()）：
    点开一次它就**永远挂在屏幕上不消失**，之后每次搜索 / 翻页
    都能看见它 —— 看着就像"每次搜索都弹镜像源选择"。
    v2.0.4 起改成模态，但"多点几次叠出好几个窗口"仍在。
  - 本次针对这个现象做了三层加固：
      1. 单例：整个进程只创建『下载源设置』这一个窗口，
         重复点只把它顶到前面，绝不叠出第二个；
      2. 进模组浏览窗口时自动收掉还挂着的残留窗口（老版本行为
         或用户手动开着忘了关，都不会再挡住界面）；
      3. 测速（『测一下哪个能用』）的提示框标题和正文都写明
         "这是测速结果，跟搜索无关"，不再被误认成搜索报错。

【已实测确认】
  在 v2.0.3 / v2.3.1 / v2.3.5 三个版本上逐一抓取（拦截 QDialog 的
  exec / show / open 与所有 QMessageBox），模组搜索的每个动作
  （打开窗口、切页签首搜、点搜索、换下载源、翻页）**一个弹窗都没有**；
  只有用户主动点『镜像源设置』才会弹。
  这条"搜索流程零弹窗"已固化成自动化回归测试。

v2.3.2  数据安全 + 日志搜索（2026-11-03）
----------------------------------------------------------------

【健壮性：所有配置写入改为原子替换（重要）】
  - 以前全项目 31 处直接用 open(path, "w") 写文件。open(..., "w")
    会先把原文件截断成 0 字节再往里写，只要写到一半出事
    （断电、任务管理器强杀、磁盘写满、json.dump 中途抛异常），
    文件就永久变成空的或半截：
        servers.json      服务器列表、排序、自定义图标、最近开服时间
        server.properties 变空文件，服务器直接起不来
        各种 YAML 配置     同上
  - 新增 core/fsutil.py：写同目录临时文件 → flush + fsync →
    os.replace 原子替换，结果是"要么旧的、要么新的"，没有中间态。
  - 临时文件名带进程号-线程号，两个线程同时写同一文件不会抢名字。
  - os.replace 遇到只读属性 / 被杀毒软件短暂占用时退避重试，
    顺带解决了"从 zip 解压出来的文件保存失败"这个老问题。
  - 用户数据（servers.json、server.properties、各类 YAML、run.bat）
    保存时轮转 3 份快照（.bak / .bak.2 / .bak.3）。
  - servers.json 读取改为自愈：主文件损坏时自动退回 .bak，
    重新打开软件还能看到完整的服务器列表。

【控制台：日志搜索与只看问题】
  - 每个控制台上方新增搜索条，Ctrl+F 唤出（输入框右侧也有「查找」按钮）：
      回车找下一个 / Shift+回车上一个 / 到底自动绕回开头
      所有命中处标底色，右侧显示命中数量，无匹配直接提示
  - 「只看问题」：只显示 WARN / ERROR 级别和报错堆栈，
    排查崩溃不用在几千行 INFO 里翻。关掉后之前跳过的行会补回来。
  - Esc 关闭搜索条并恢复全部日志。
  - 顺带修掉两个隐藏问题：
      · <br> 在 Qt 里只是行分隔符、不产生文本块，导致
        setMaximumBlockCount(5000) 从来没生效过 —— 挂机久了控制台
        会无限增长；现在改成真正的文本块，上限真的起作用了。
      · 指令历史与补全的初始化被误缩进进了 set_colors()，
        浮动控制台（Ctrl 调出的独立窗口）里发指令会
        AttributeError，而且换配色还会清空历史。

【服务器列表：搜索筛选】
  - 列表上方新增搜索框（Ctrl+F），支持多关键字空格分隔：
      "fabric 1.20"  → 加载器 + 版本同时匹配
      "原版"          → 匹配中文加载器名
      名称 / 版本 / 加载器 / 存档名 / 备注都可以搜
  - 筛选后所有"第 N 行是哪台服"的映射同步切换（表格行号、图标序号、
    右键菜单、双击启停、状态列、控制台页签），不会出现
    "选中的是 A、操作的却是 B"。
  - 筛选状态下禁止拖动排序（否则保存的自定义顺序会把隐藏的服务器
    挤到错误位置）；Esc 清空筛选。
  - 导入 / 初始化完成后，若目标服务器被筛选藏起来，会自动清空筛选
    再定位选中。

v2.1.2  修复启动服务器后 UI 无响应（2026-11-04）
----------------------------------------------------------------

【Bug 修复：启动服务器后 MCSM 无响应】
  - 现象：启动服务器后 MCSM.exe 无响应，CPU 低但电源使用非常高。
  - 根因1：_detect_running_servers 在 500ms 后运行，发现刚创建的 .mcsm_pid，
    把 self.procs[k] 从 QProcess 替换成 ReattachedProcess，破坏服务器监控。
  - 根因2：_check_alive() 用 subprocess.run(["tasklist"]) 阻塞主线程，
    _tail_log 每秒调一次，导致 UI 卡死。
  - 修复1：_detect_running_servers 跳过已在 self.procs 中的服务器。
  - 修复2：_check_alive/kill/write 全部改用 ctypes Windows API（非阻塞）。
  - 修复3：_tail_log 轮询间隔从 1 秒增加到 3 秒。

v2.1.1  修复 voice_host 正则误读注释为值（2026-11-04）
----------------------------------------------------------------

【Bug 修复：voice_host 空值时正则误读下一行注释】
  - 现象：当配置文件中 voice_host= 为空值时，正则的 \s* 匹配了换行符，
    跳到下一行把注释内容（如 # If players are allowed...）当成 voice_host 的值。
  - 根因：Python 正则 \s 包含 \n，\s* 跨行匹配。
  - 修复：read_svc 和 apply_svc 的正则中 \s* 改为 [ \t]*，
    只匹配空格和 tab，不匹配换行符。

----------------------------------------------------------------

【管理器退出时自动弹出独立控制台】
  - 关闭管理器时，若仍有服务器在运行，为每个服务器弹出独立 cmd 窗口。

  - 若存活，自动恢复管理：控制台页签、日志 tail、停止按钮。
  - 若已退出，自动清理残留 PID 文件。

【PID 文件管理】
  - 服务器启动时写入 .mcsm_pid，正常停止/崩溃时自动清理。
  - ReattachedProcess 包装类提供与 QProcess 一致的接口（write/state/kill）。

  · 退出前会弹窗提示：『服务器会继续在后台运行，不再受管理器

  · 想优雅停服请用界面上的『停止』按钮（仍会先 save 存档再关）。

【2. FerriteCore 在 1.21.3 上崩溃（Mixin 注入失败）修复】
  · 症状：1.21.3 fabric 服装 FerriteCore 7.1.0 后启动即崩，
    日志关键错误 Mixin apply for mod ferritecore failed ...
    @Shadow field collisionShape was not located in the target class。
  · 原因：7.1.0 普通版通过 Mixin 改 BlockState 类，但 1.21.3 里
    collisionShape 字段位置变了，注入失败，启动阶段直接崩。
  · 修复：1.21.3 + fabric/quilt 服安装或更新 FerriteCore 时，
    自动选用官方 hotfix 版（ferritecore-7.1.0-hotfix-fabric.jar），
    其他 MC 版本不受影响（实测 1.21.4 仍用 7.1.1 原版）。
  · 已装崩服的旧 jar：删掉 mods 里的普通版，在『模组』页点更新
    即可换成 hotfix 版（或手动删除后重新安装）。

【3. 自动备份在服务器运行时失效修复】
  · 症状：服务器开着时自动备份复制不了存档内容（拿到的区块文件
    是写了一半的）。
  · 修复：触发自动备份时先通过控制台发 『save-all flush』，
    等存档刷进磁盘再复制，备份结果与停服时一致。
  · 原版 / Fabric / Paper 服务器均支持该指令，无需额外插件。

v1.6.1  内存单位动态切换与智能换算（GB / MB）（2026-10-26）
----------------------------------------------------------------

【初始化界面（创建服务器）】
  · 「最小内存 / 最大内存」输入框旁新增单位下拉框（G / MB，默认 G）。
  · G 模式：允许一位小数（0.5 步进），范围 1.0 ~ 64.0 G，
    默认 1.0G / 4.0G。
  · MB 模式：整数，范围 512 ~ 65536 MB，步长 512，
    默认 1024 / 4096。
  · 智能换算：
      - MB → G：除以 1024，整除显示整数（3072 → 3），
        除不尽保留一位小数（3584 → 3.5）。
      - G → MB：乘以 1024 取整（3.5 → 3584）。
  · 创建时统一转为整数 MB 写入服务器配置（如 xms=1024、xmx=4096）。

【服务器配置 -> 启动设置】
  · 内存输入框旁同样有 G / MB 单位下拉框。
  · 智能回显：读取已存配置时，数值能被 1024 整除（如 4096）
    自动以 G 展示（4.0G）；除不尽（如 3584）自动切到 MB 展示。
  · 保存时统一按当前单位换算成整数 MB，写入 servers.json，
    run.bat 保持 -Xms4096M 格式。
  · Aikar 同步（最大=最小）改为按整数 MB 桥接，两个框单位
    不一致也不会串数值。

【数据持久化】
  · servers.json 里 xms / xmx 永远存整数 MB（如 4096），
    绝不存带 "G" 的字符串或小数；主界面启动读取时永远是
    安全可用的整数 MB。

  · Forge / NeoForge 元数据接入 BMCLAPI2 加速，失败自动回退官方源。
  · NeoForge 1.20.1（47.x）镜像缺失时自动用官方源兜底。
  · 模组哈希批量查询 / 更新接口自动走镜像，失败回退官方。

  · 官方 CDN 自动替换为 MCIM 镜像加速。
  · 新增 Fractureiser 木马特征扫描，命中即删除并拒装。
  · 下载支持断点续传（Range），网络闪断不用从头下。

v6.0.0  发布版（2026-10-22）
----------------------------------------------------------------

【安装与发布】
  · 新增图形安装程序：双击 安装.bat，可勾选
      - 自动安装 Python（本机没有 Python 3.9+ 时，下载并静默安装 Python 3.12）
      - 安装 PySide6 界面库（已安装则自动跳过；失败会自动换国内镜像重试）
      - 创建桌面快捷方式
    并可自选安装目录，不需要管理员权限。
  · 新增卸载程序：卸载.bat，可选择删除程序文件、配置和桌面快捷方式。
  · 正式发布包不再附带 check_*.py、t_toggle.py 等开发工具，体积更小。
  · 新增 pack.py 打包脚本：发布包自动校验，拒绝 __pycache__、用户配置混入。

【服务器核心安装】
  · Paper 下载全面改用官方 Fill v3 接口。
    原 api.papermc.io/v2 已整体下线（实测全部返回 410），旧代码会先失败再回退。
  · Paper 旧版本（1.21.3 / 1.21.4，甚至 1.7.10 等）在 fill 站仍可下载，
    软件会自动处理；这些版本被官方标记为 UNSUPPORTED，不再修 bug / 补安全漏洞。
  · Fabric、Paper、Forge、NeoForge 的安装和加载器更新全部重新测试。
  · 修复 Forge 加载器更新永远提示“查不到版本”的问题。
  · 修复 Paper 加载器更新因参数名过旧而直接报错的问题。
  · Forge / NeoForge 更新会自动寻找可用的 Java；服务器配置里保存的 Java 也会带过去。
  · 更新加载器时（Fabric 服）可选“同时更新 Fabric API 前置模组”，默认勾选；
    旧版 Fabric API 会改名成 .old 留底，避免新旧两个版本同时加载。

【扫描与识别】
  · 加载器识别改为读取 jar 内部特征，不再只看文件名：
      - Paper 装成 server.jar 也能正确识别为 paper；
      - 原版 server.jar 不会再被误判成 Paper。
  · 扫描改到后台线程，服务器多、world 大时界面不再卡住；
    扫描过程中切换总目录会自动按新目录重新扫描。
  · 存档选择优先使用 server.properties 里的 level-name，
    并排除 backups 目录，不会再拿备份存档当主存档显示。

【启动 / 搬迁 / 导入】
  · 统一搬迁、拖放导入、工具栏“导入地图”全部改为后台线程，复制大存档不卡界面。
  · 搬迁/导入进行中关闭窗口会先确认，避免留下复制了一半的文件夹。
  · 启动时如果上次的总目录不存在（例如盘符换了），不再弹框卡住，只在状态栏提示。

【界面】
  · 顶部文字按钮新增悬停淡入、按下回弹动画。
  · 移除描边功能，只保留粗体设置。
  · 显示设置里的“PCL 风格”改名为“选中与悬停效果”，相关选项改成更直白的名字。
  · 移除“PCL 龙猫蓝”预设配色。
  · 主题配置损坏（例如颜色字段被写成 false）时自动恢复默认，避免界面异常。

【稳定性 / 清理】
  · 修复通过 Modrinth 下载/更新模组必定失败的问题（下载函数参数不匹配）。
  · 修复“已装 Fabric API 检测不到”的问题（之前扫错了目录）。
  · 修复主题文件中残留旧配色/坏值时界面异常的问题。
  · 修复关闭窗口时，后台服务器进程可能导致程序卡死或闪退的问题：
      定时器现在挂载了父对象；强杀进程后等待 500ms 防止出现僵尸进程。
  · 修复多开备份冲突（改用字典按服隔离）。
  · 修复 `analyze.py` 因旧函数名导致的静默报错。
  · 修复 `loaderup.py` 的正则识别不到新版 `neoforge` 的问题。
  · 修复扫描时网络接口查询报错不提示的问题。
  · 清理死代码 100 余处：重复定义的方法、没有任何入口的功能、
    未被调用的函数/常量、未使用的导入等。
  · 回归测试脚本改为写临时配置，不再覆盖用户的 theme.json。
